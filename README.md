# gotree

Небольшая CLI-утилита на Go для потокового обхода файловой системы и вывода дерева директорий.

Поддерживает человекочитаемый вывод в терминал и машиночитаемый формат JSON Lines для использования в пайплайнах.

## Возможности

- Потоковый обход файловой системы через `iter.Seq2`.
- Два формата вывода: `tree` и `jsonl`.
- Автоматическое определение формата по типу `stdout`.
- Отображение только директорий.
- Скрытие служебных файлов и директорий по умолчанию.
- Возможность показать все файлы с помощью `-a`.
- Передача пути, родителя, глубины вложенности и типа объекта.
- Поддержка символических ссылок без рекурсивного перехода по ним.
- Работа без загрузки всего дерева в память.

## Требования

- Go 1.23 или новее.

## Установка и сборка

Клонируйте репозиторий и перейдите в директорию проекта.

Установите зависимости:

```bash
go mod tidy
```

Соберите исполняемый файл:

```bash
go build -o gotree ./cmd/gotree
```

После сборки утилиту можно запускать через `./gotree`.

Для запуска без предварительной сборки:

```bash
go run ./cmd/gotree
```

## Использование

Общий синтаксис:

```bash
gotree [flags] [path]
```

Если путь не указан, используется текущая директория.

### Доступные флаги

| Короткий | Длинный | Описание |
|---|---|---|
| `-a` | `--all` | Показать скрытые и служебные файлы и директории |
| `-d` | `--dirs-only` | Выводить только директории |
| `-f` | `--format` | Формат вывода: `auto`, `tree`, `jsonl` |
| `-h` | `--help` | Показать справку |

По умолчанию используется `--format auto`.

Короткие флаги передаются отдельно: `-a -d`, а не `-ad`.

### Примеры

Вывести дерево текущей директории:

```bash
./gotree
```

Вывести дерево указанного проекта:

```bash
./gotree -f tree ./backend
```

Показать только директории:

```bash
./gotree -d -f tree .
```

Показать все файлы, включая скрытые и служебные:

```bash
./gotree -a -f tree .
```

Вывести дерево в JSON Lines:

```bash
./gotree -f jsonl .
```

Сохранить структуру проекта в файл:

```bash
./gotree . > tree.jsonl
```

Найти все Go-файлы через `jq`:

```bash
./gotree . | jq 'select(.type == "file" and (.name | endswith(".go")))'
```

## Форматы вывода

### Tree

Предназначен для чтения человеком.

```text
gotree/
├── README.md
├── cmd/
│   └── gotree/
│       └── main.go
├── go.mod
├── go.sum
└── internal/
    ├── output/
    │   ├── pipeline.go
    │   └── terminal.go
    └── walker/
        └── walker.go
```

Для принудительного использования:

```bash
./gotree -f tree
```

### JSON Lines (JSONL)

Предназначен для обработки другими программами.

Каждая строка содержит отдельный JSON-объект. Полное дерево не требуется загружать в память.

Пример:

```jsonl
{"path":"/project","name":"project","depth":0,"type":"directory","is_last":true}
{"path":"/project/cmd","name":"cmd","parent":"/project","depth":1,"type":"directory","is_last":false}
{"path":"/project/main.go","name":"main.go","parent":"/project","depth":1,"type":"file","is_last":true}
```

Поля объекта:

| Поле | Описание |
|---|---|
| `path` | Абсолютный путь к объекту |
| `name` | Имя файла или директории |
| `parent` | Абсолютный путь к родительской директории |
| `depth` | Глубина относительно корня |
| `type` | `file`, `directory`, `symlink` или `other` |
| `is_last` | Является ли объект последним среди отображаемых соседей |

У корневого элемента `depth = 0`, а поле `parent` отсутствует.

### Автоматическое определение формата

В режиме `auto` утилита проверяет, подключён ли стандартный поток вывода (`stdout`) к терминалу.

- Если подключён, используется `tree`.
- Если вывод перенаправлен в файл или пайплайн, используется `jsonl`.

Пример:

```bash
./gotree . | jq .
```

Здесь JSONL выбирается автоматически.

## Фильтрация файлов

По умолчанию утилита исключает скрытые файлы и директории, имена которых начинаются с точки:

```text
.git/
.idea/
.DS_Store
.env
.gitignore
```

Дополнительно исключаются служебные директории:

```text
node_modules/
__pycache__/
venv/
dist/
build/
coverage/
vendor/
```

Для отключения фильтрации:

```bash
./gotree -a
```

Фильтрация выполняется до рекурсивного обхода. Исключённые директории не читаются.

## Возможные улучшения

- Пользовательские исключения через `-e` / `--exclude`.
- Ограничение глубины обхода через `--max-depth`.
- Подсчёт количества файлов и директорий.
- Поддержка `.gitignore`.
- Дополнительные форматы вывода.
- Тесты обхода, фильтрации и терминального форматирования.
